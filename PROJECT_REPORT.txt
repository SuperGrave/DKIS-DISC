1. プロジェクト概要
--------------------------------------------------------------------------------

  名称: dkis-disc（リポジトリ: DKIS-DISC）
  役割: Discord 上で動作する DKIS 互換の軽量 AI ボット。OpenAI とツール連携。
        パッケージ名 line_bot_app は歴史的経緯（旧 LINE 実装から流用）であり、
        本プロジェクトの実行対象は Discord のみ。

  技術スタック（要点）:
  - Python 3.12+（requires-python >=3.12）
  - 依存管理: uv（pyproject.toml / uv.lock）
  - Discord: discord.py >= 2.6（常時接続 Client）
  - AI: OpenAI Chat Completions API（SDK openai）
  - 永続化（任意）: Supabase（PostgreSQL）、supabase SDK
  - 設定ファイル: dist/settings.json（拡張: DKIS_SETTINGS_PATH）
  - デプロイ想定: Render（render.yaml Blueprint）、GitHub Actions keepalive

  明示的に「含まない」もの（README 同旨）:
  - Web フロント、SSE、音声・メディア再生、ローカルファイル操作 GUI

3. アーキテクチャ（会話処理の流れ）
--------------------------------------------------------------------------------

  3.1 通常メッセージ（on_message）

    1) ボット以外のメッセージを受信
    2) channel_settings: 当該チャンネルが enabled=on でないと無視（既定オフ）
    3) channel_kind=debug: 通常会話は行わず案内のみ（専用コマンドは後続実装前提）
    4) known_line_users ベースのユーザー設定: talk_with_kiritan 等
    5) DISCORD_MESSAGE_MODE（all / mention / hybrid / slash_only）と
       response_criteria で「全件 or メンションのみ」等
    6) user_role による UTC 日次トークン上限チェック（超過時は案内のみ）
    7) AIResponder.reply → チャンク単位で Discord 送信（typing 中）
    8) 直近10分に応答したチャンネルを記録 → Presence 集計に利用

  3.2 応答エンジン（DiscordBrain）

    - OpenAI chat.completions、DKIS 形式パース・ツール実行・RETRY 連鎖
    - 会話履歴はプロセス内メモリのみ（再起動で消失）。永続は Supabase 側の
      記憶ファイル・ユーザー別統計・中期記憶など。

  3.3 Slash Commands（HTTP Interactions: POST /interactions）

    - Ed25519 署名（DISCORD_PUBLIC_KEY）
    - get_setting / set_setting / channel_setting
    - 応答は split_line_text(..., max_chunks=1) のため長文は約2000字で切れる

--------------------------------------------------------------------------------
4. Discord 固有機能
--------------------------------------------------------------------------------

  4.1 スラッシュコマンド（登録名は実装どおり snake_case）

    /get_setting   ユーザー別・実行チャンネル別の設定表示（build_settings_text）
    /set_setting   許可キー＋値。visitor は using_model 変更不可
    /channel_setting
                   管理者: true/false でチャンネル有効化
                   operator: debug / normal で channel_kind

  4.2 Presence（ステータスバー）

    例: run in Nsb (A/B/Cch) RAM:xx%
    - 括弧内（左から）: 直近10分に応答したch数 / enabled なch数 /
      ボットが view+send+read_history を満たすテキストch総数
    - RAM: cgroup の memory.current/max が取れる環境のみ%。
    - DISCORD_STATUS_MODE により enabled=0 のとき sleep 表示のモードあり

  4.3 起動時通知（1.2.3 時点・一本化済み）

    - maybe_build_worker_boot_greeting で「きりたん風」短文＋
      オプトイン（notify_on_restart）向け履歴用データ
    - 投稿先:
      * Supabase に channel_kind=debug の行が1件以上ある → その全チャンネルへ
      * debug が0件 → 環境変数 DISCORD_CHANNEL_ID のチャンネルのみへ
    - 本文: 起動時刻(UTC)、サーバー数、会話可能ch、登録ユーザー数、
      UTC 本日トークン集計等＋任意で起動あいさつブロック

    ※ 旧「毎日メッセージ専用チャンネル」機能は 1.2.3 で削除済み。
      DB に discord.daily_message_channel_id が残っていても未参照。

5. 権限・レート制限（ユーザー）
--------------------------------------------------------------------------------

  user_role（known_line_users.user_role、既定 visitor）:
  - visitor:  日次 1,000,000 トークン（UTC）、using_model 変更不可
  - member:   日次 10,000,000 トークン
  - operator: 日次 10,000,000 トークン、デバッグルーム debug/normal 切替可

  operator の付与:
  - 環境変数 DISCORD_OPERATOR_USER_IDS（カンマ区切り）
  - または DISCORD_ADMIN_USER_IDS が operator 判定に結合される箇所あり（実装参照）
  - DB の user_role 列（Supabase 反映後）

--------------------------------------------------------------------------------
6. Supabase スキーマ（概要）
--------------------------------------------------------------------------------

  適用手順: Supabase SQL Editor で dist/supabase_schema.sql を実行。

  memory_files      (line_user_id, filename) PK — 実体は Discord user_id
  user_settings     setting_key ごと全員共通1値
  channel_settings  channel_id ごと enabled, response_mode, process_notice,
                    channel_kind (normal/debug) 等
  known_line_users  line_user_id PK — Discord user_id 相当
                    会話設定、user_role、日次トークン、中期記憶、起動履歴差し込み等

  サーバー側は通常 SUPABASE_KEY に service_role を設定（RLS バイパス想定）。

8. デプロイ・運用
--------------------------------------------------------------------------------

  - Render: build uv sync / start uv run python main.py
  - ヘルス: GET / → {"ok": true, "service": "dkis-disc-bot"}
  - Discord Developer Portal: MESSAGE CONTENT INTENT 必須（本文取得）

  運用初期チェックリスト（README 要約）:
  1) supabase_schema.sql 適用
  2) DISCORD_OPERATOR_USER_IDS 等
  3) DISCORD_CHANNEL_ID 設定（debug 未設定時の起動通知用）
  4) 起動通知を専用chで受けたい場合 /channel_setting value:debug
