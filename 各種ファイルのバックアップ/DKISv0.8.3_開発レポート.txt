# DKISv0.8.3 開発レポート

## 📋 プロジェクト概要

**DKIS（Drive Kiritan to Issho System）v0.8.3** は、v0.8から引き続き改良を重ねた、複数デバイス対応を強化した次世代型音声対話システムです。マルチデバイス環境での音声設定の柔軟性、統計情報の可視化、UI/UXの大幅な改善が実装されました。

### v0.8.3のテーマ
- **マルチデバイス対応の強化**: 複数デバイスでの同時利用を想定した設定機能
- **統計情報の可視化**: システムの稼働状況をリアルタイムで把握
- **UI/UXの洗練**: 使いやすさと見やすさの両立
- **AI動作の最適化**: より自然で賢い対話の実現

## 🆕 v0.8 → v0.8.3 の主要変更点

### 🎙️ 音声設定の2層分離（最重要）

#### **問題点（v0.8）**
複数デバイスで同時にページを開いた場合：
- 「きりたんの読み上げ」設定がサーバー側の合成とクライアント側の再生の両方を制御
- デバイスAでON、デバイスBでOFFにすると矛盾が発生
- どちらかのデバイスの希望には必ず添えない状況に

#### **解決策（v0.8.3）**
音声設定を2層に分離：

**1. サーバー側設定：「PCで音声を合成する」**
- 全デバイスで共有される単一の設定
- どのデバイスからでも変更可能
- 変更時にSSEで全クライアントに同期
- LocalStorageには保存しない

**2. クライアント側設定：「音声を再生する」**
- デバイスごとに独立した設定
- LocalStorageに保存
- サーバー側の合成がOFFの場合は無効化（グレーアウト）

#### **実装**

**サーバー側（main.py）**:
```python
# TTS状態変更時に全クライアントへ通知
@app.route('/set_voice_mode', methods=['POST'])
def set_voice_mode():
    enabled = data.get('enabled', True)
    
    if enabled:
        set_unmute()
    else:
        set_mute()
    
    # 🆕 状態変更を全クライアントに配信
    send_event("tts_enabled_changed", {
        "enabled": enabled
    })
    
    return jsonify({"ok": True, "enabled": enabled})
```

**クライアント側（state.js）**:
```javascript
// 🆕 状態を2つに分離
export const state = {
  ttsEnabled: true,        // サーバー側：音声合成するか（全デバイス共有）
  voicePlaybackMode: true, // クライアント側：音声再生するか（デバイスごと）
};
```

**同期処理（main.js）**:
```javascript
// 🆕 SSEイベントで全デバイスに同期
function handleTtsEnabledChangedEvent(msg) {
  const { enabled } = msg;
  state.ttsEnabled = enabled;
  if (elements.ttsEnabledPanel) {
    elements.ttsEnabledPanel.checked = enabled;
  }
  updateVoicePlaybackAvailability();
}
```

**相互依存制御（main.js）**:
```javascript
// 🆕 TTS合成がOFFの場合は音声再生設定を無効化
function updateVoicePlaybackAvailability() {
  const ttsEnabled = state.ttsEnabled;
  
  elements.voicePlaybackModePanel.disabled = !ttsEnabled;
  elements.volumeSliderPanel.disabled = !ttsEnabled;
}
```

**効果**:
- デバイスAでTTS合成をOFF → 全デバイスで音声再生設定が無効化
- デバイスBで音声再生をOFF → デバイスBだけ音声が流れない
- TTS合成がOFFの時に音声認識が再開しない問題を回避
- 複数デバイス環境でも矛盾のない設定管理

**影響ファイル**:
- `main.py`: TTS状態変更イベント配信
- `static/js/state.js`: 状態を2層に分離
- `static/js/main.js`: 同期処理・相互依存制御
- `static/js/api.js`: tts_enabled_changedイベントリスナー
- `templates/index.html`: UI分離（2つのチェックボックス）
- `static/css/styles.css`: 無効化時のスタイル

### 📊 統計情報システム（運用性向上）

#### **新機能**
システムの稼働状況をリアルタイムで可視化：

**カウント項目**:
1. **ユーザー入力回数**: `/callback` エンドポイントへのリクエスト
2. **RETRY処理回数**: `/notify/retry_input` 経由のRETRY
3. **きりたん返答回数**: `enqueue_utterance()` 呼び出し回数
4. **AI処理要求回数**: `ask_chatgpt()` 呼び出し回数（メイン処理、検索要約、テキスト要約、地名解決など全て含む）
5. **コマンド実行回数**: コマンドごとの実行回数（SPEAK、SEARCH、PLAY-MUSIC等）
6. **サーバー起動日時**: システム起動時刻
7. **稼働時間**: 起動からの経過時間（リアルタイム更新）

#### **実装**

**サーバー側（main.py）**:
```python
# 🆕 統計情報カウンター
server_start_time = datetime.datetime.now()

    "user_inputs": 0,
    "retry_inputs": 0,

def increment_stat(key, subkey=None):

                statistics[key] = {}
            statistics[key][subkey] = statistics[key].get(subkey, 0) + 1
        else:
            statistics[key] = statistics.get(key, 0) + 1

# 循環import回避のため関数注入方式

from core.voicevox_handler import set_increment_stat_func as set_voicevox_increment_stat
from core.functions import set_increment_stat_func as set_functions_increment_stat
```

### 🔊 音量調整のクライアント側実装

#### **問題点（v0.8）**
- 音量調整がVOICEVOXへのリクエストパラメータで実施
- スライダーを動かしても次の音声から反映
- 再生中の音声にリアルタイムで反映されない

#### **解決策（v0.8.3）**
- VOICEVOXには常に `volume=1.0` を送信
- ブラウザのAudio要素で音量を調整
- スライダーを動かすと再生中の音声に即座に反映

#### **実装**
```javascript
// 🆕 再生中のAudio要素への参照を保持
let currentAudioElement = null;

function playSegment(utterId, segment) {
  const audio = new Audio(url);
  audio.volume = state.volume;
  currentAudioElement = audio;  // 🆕
  
  audio.onended = () => {
    if (currentAudioElement === audio) {
      currentAudioElement = null;  // 🆕
    }
    playNextSegment();
  };
}

// 🆕 スライダーでリアルタイム調整
elements.volumeSliderPanel.addEventListener("input", () => {
  const volume = parseFloat(elements.volumeSliderPanel.value) / 100;
  saveSetting('volume', volume);
  
  // 再生中の音声にリアルタイムで反映
  if (currentAudioElement) {
    currentAudioElement.volume = volume;
  }
});
```

**効果**:
- スライダーを動かすと即座に音量が変わる
- ちょうどいい音量を探しやすい
- デバイスごとに最適な音量を設定可能

**影響ファイル**:
- `static/js/main.js`: Audio要素参照管理、リアルタイム音量調整

### 📏 吹き出しテキスト自動リサイズの改善

#### **問題点（v0.8）**
- 文字数だけでフォントサイズを決定
- スマホでは完璧にフィットするが、PCでは下に大きな余白
- デバイスごとの吹き出しサイズの違いを考慮していない

#### **解決策（v0.8.3）**
- 吹き出しの実際の高さを測定
- 二分探索アルゴリズムで最適なフォントサイズを自動計算
- どんなデバイスでもぴったりフィット

#### **実装**
```javascript
// 🆕 二分探索による最適化
function resizeBubbleText(textElement) {
  const bubble = document.getElementById('current-bubble');
  
  // 吹き出しの利用可能な高さを計算
  const availableHeight = bubble.clientHeight - paddingTop - paddingBottom;
  
  // 二分探索でフィットするフォントサイズを見つける
  let minFontSize = 0.8;  // 最小サイズ
  let maxFontSize = 4.0;  // 最大サイズ
  let bestFontSize = minFontSize;
  
  for (let i = 0; i < 15; i++) {  // 最大15回の反復
    const testFontSize = (minFontSize + maxFontSize) / 2;
    textElement.style.fontSize = `${testFontSize}em`;
    
    const textHeight = textElement.scrollHeight;
    const targetHeight = availableHeight * 0.95;  // 95%まで使用
    
    if (textHeight <= targetHeight) {
      bestFontSize = testFontSize;
      minFontSize = testFontSize;
    } else {
      maxFontSize = testFontSize;
    }
    
    if (maxFontSize - minFontSize < 0.05) break;
  }
  
  textElement.style.fontSize = `${bestFontSize}em`;
}
```

**アルゴリズム**:
1. 吹き出し要素の高さとパディングを測定
2. 利用可能な高さを計算
3. フォントサイズを0.8em～4.0emの範囲で二分探索
4. テキストがちょうど収まる最大のフォントサイズを発見
5. 最大15回の反復で収束（通常5～8回で完了）

**効果**:
- スマホでもPCでもぴったりフィット
- 余白を最小限に
- デバイスサイズに自動対応

**影響ファイル**:
- `static/js/ui.js`: `resizeBubbleText()` 関数の完全書き換え

### 🎵 Spotify KeepAlive条件の改善

#### **問題点（v0.8）**
- 4'33"を再生中の場合のみ継続再生
- 他の曲が選ばれているが一時停止中の場合は何もしない
- 長時間一時停止するとSpotify接続が切れる可能性

#### **解決策（v0.8.3）**
- トラックIDが何であっても、再生状態が停止中なら4'33"を再生
- より積極的に接続を維持

#### **実装**
```python
# 🆕 再生状態も確認
def _keepalive_tick():
    current_track_id = get_current_track_id()
    is_playing = is_spotify_playing()  # 🆕
    
    if current_track_id is None:
        # 何も再生していない → 4'33"を再生
        play_silent_track()
    elif current_track_id == SILENT_TRACK_ID:
        # 4'33"を再生中 → 継続再生
        play_silent_track()
    elif not is_playing:  # 🆕
        # 他の曲が選ばれているが再生中でない → 4'33"を再生
        play_silent_track()
    else:
        # ユーザーが他の曲を再生中 → 何もしない
        pass
```

**変更前の条件**:
1. トラックIDが `None` → 4'33"を再生
2. トラックIDが `4'33"` → 継続再生
3. それ以外 → 何もしない（❌ 一時停止が放置される）

**変更後の条件**:
1. トラックIDが `None` → 4'33"を再生
2. トラックIDが `4'33"` → 継続再生
3. **再生状態が停止中** → 4'33"を再生（🆕）
4. 再生状態が再生中 → 何もしない

**効果**:
- ユーザーが曲を一時停止しても、keepaliveが4'33"を流してSpotify接続維持
- 接続が切れる可能性を大幅に低減

**影響ファイル**:
- `core/spotify_handler.py`: `_keepalive_tick()`, `update_keepalive_status_now()`

**効果**:
- 「お気に入りからそのままかけて」で即座に1曲を選んで再生
- 選択肢を提示して待たせることがない
- より自然でスムーズな対話

### 🔧 バグ修正と最適化

#### **SSEイベント重複防止の改善**
```python
# 🆕 設定変更系イベントは重複チェックをスキップ
def send_event(ev: str, data: dict):
    if ev not in ("tts_enabled_changed",):
        # 通常イベントは重複チェック
        key = _mk_key(ev, uid, reason, data)
        if key in _recent_keys:
            return
        _recent_keys.append(key)
    
    # 🆕 設定変更イベントは毎回送信
    payload = {"type": ev, **data}
    # ...全クライアントに送信
```

**理由**:
- ON→OFF→ON→OFFと頻繁に切り替えると、重複チェックで弾かれる
- 設定変更は頻繁には起きないので、重複チェック不要
- 確実に全デバイスに届けるため

**影響ファイル**:
- `main.py`: `send_event()` 関数

```javascript
// 🆕 人間が読みやすい形式に変換
function formatUptime(seconds) {
  const days = Math.floor(seconds / 86400);
  const hours = Math.floor((seconds % 86400) / 3600);
  const minutes = Math.floor((seconds % 3600) / 60);
  const secs = seconds % 60;
  
  const parts = [];
  if (days > 0) parts.push(`${days}日`);
  if (hours > 0) parts.push(`${hours}時間`);
  if (minutes > 0) parts.push(`${minutes}分`);
  parts.push(`${secs}秒`);
  
  return parts.join(' ');
}
```

```javascript
// 🆕 二分探索による最適化
function resizeBubbleText(textElement) {
  const bubble = document.getElementById('current-bubble');
  const availableHeight = bubble.clientHeight - paddingTop - paddingBottom;
  
  let minFontSize = 0.8;
  let maxFontSize = 4.0;
  let bestFontSize = minFontSize;
  
  // 二分探索で最適なフォントサイズを発見
  for (let i = 0; i < 15; i++) {
    const testFontSize = (minFontSize + maxFontSize) / 2;
    textElement.style.fontSize = `${testFontSize}em`;
    const textHeight = textElement.scrollHeight;
    const targetHeight = availableHeight * 0.95;
    
    if (textHeight <= targetHeight) {
      bestFontSize = testFontSize;
      minFontSize = testFontSize;
    } else {
      maxFontSize = testFontSize;
    }
    
    if (maxFontSize - minFontSize < 0.05) break;
  }
  
  textElement.style.fontSize = `${bestFontSize}em`;
}
```

### 🆕 二分探索による最適化アルゴリズム

#### **吹き出しテキストの自動リサイズ**
```
目標: テキストを吹き出しにぴったりフィットさせる

アルゴリズム: 二分探索
時間計算量: O(log n) ← n=フォントサイズの範囲
反復回数: 最大15回（通常5～8回）

手順:
1. フォントサイズの範囲を設定（0.8em ～ 4.0em）
2. 中間値でテキストを描画
3. テキスト高さを測定
4. 目標高さと比較
   - 小さい → 下限を中間値に
   - 大きい → 上限を中間値に
5. 収束するまで繰り返し（精度0.05em）
6. 最適なフォントサイズを適用
```

**従来方式との比較**:
```
【v0.8】文字数ベース
- 30文字以下 → 2.5em
- 60文字以下 → 2.0em
- 100文字以下 → 1.6em
- ...固定の閾値

問題点:
- デバイスサイズを考慮しない
- 実際の表示領域を無視
- PCで大きな余白が残る

【v0.8.3】二分探索ベース
- 吹き出しの実際の高さを測定
- テキストの実際の高さを測定
- 95%フィットする最大サイズを自動計算

効果:
- どんなデバイスでもぴったりフィット
- 余白を最小限に
- デバイス差を自動吸収
```

### 🆕 SSE重複防止の選択的適用

#### **設計思想**
```python
# 通常のイベント: 重複チェック実施
# - reply, synth_done など頻繁に発生するイベント
# - 同じイベントが短時間に複数回送信される可能性

# 設定変更イベント: 重複チェックをスキップ
# - tts_enabled_changed など低頻度イベント
# - ON→OFF→ONと切り替えても全て送信する必要
# - 確実に全デバイスに届ける

def send_event(ev: str, data: dict):
    if ev not in ("tts_enabled_changed",):
        # 通常イベントのみ重複チェック
        key = _mk_key(ev, uid, reason, data)
        if key in _recent_keys:
            return
        _recent_keys.append(key)
    
    # 全クライアントに送信
```

### スレッドセーフ実装

```python
statistics_lock = Lock()

def increment_stat(key, subkey=None):
    """スレッドセーフな統計カウント"""
    with statistics_lock:
        # クリティカルセクション
        if subkey:
            statistics[key][subkey] = statistics[key].get(subkey, 0) + 1
        else:
            statistics[key] = statistics.get(key, 0) + 1

def get_statistics():
    """スレッドセーフな統計取得"""
    with statistics_lock:
        # 完全なコピーを返す
        return {
            "user_inputs": statistics.get("user_inputs", 0),
            "commands": statistics.get("commands", {}).copy()
        }
```

**重要性**:
- Flaskは複数スレッドで動作
- 統計情報への同時アクセスが発生
- Lockによる排他制御で競合状態を回避

## 🔍 技術詳細：TTS設定同期システムの実装

### シーケンス図

```
デバイスA            Flask Server         デバイスB
   │                      │                  │
   │ TTS ON/OFFクリック   │                  │
   ├──POST /set_voice_mode→                 │
   │                      │                  │
   │              set_mute()/set_unmute()    │
   │                      │                  │
   │              send_event("tts_enabled_  │
   │              _changed", {enabled: ...}) │
   │                      ├─SSE──────────────┤
   │                      │                  │
   │←──SSE────────────────┤                  │
   │                      │                  ▼
   │                      │    handleTtsEnabledChangedEvent()
   │                      │    state.ttsEnabled = enabled
   ▼                      │    updateVoicePlaybackAvailability()
handleTtsEnabledChanged  │                  │
Event()                  │                  │
state.ttsEnabled=enabled │                  │
updateVoicePlayback      │                  │
Availability()           │                  │
   │                      │                  │
   ▼ UI更新               │                  ▼ UI更新
チェックボックス更新      │            チェックボックス更新
再生設定有効/無効         │            再生設定有効/無効
```

### 状態整合性の保証

**問題**: 複数デバイスで状態の不整合が起きる可能性

**解決策**:
1. **サーバーを唯一の真実の源（Single Source of Truth）**とする
2. クライアントからの変更はすべてサーバー経由
3. サーバーから全クライアントへSSEでブロードキャスト
4. クライアントは受信した状態で上書き更新

**コード**:
```javascript
// クライアント側は受信した値を信頼
function handleTtsEnabledChangedEvent(msg) {
  state.ttsEnabled = msg.enabled;  // サーバーの状態を絶対とする
  elements.ttsEnabledPanel.checked = msg.enabled;
}
```
